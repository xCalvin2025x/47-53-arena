# 把 v53 的「Small arena（小型竞技场）」移植到 v0.47.05

## 结论先说

已经生成好了可直接使用的文件：**`47_small_arena.txt`**

把它改名成 `arena.txt`，覆盖到 v0.47.05 游戏目录的 `data\init\arena.txt`（**先备份原文件**），
启动游戏进入 Object Testing Arena，看到的就是小型竞技场：一片草地中央一个石墙围起来的沙地椭圆场，
南边有一小段沙地出口。

因为 0.47 的竞技场尺寸是**写死的 144×144、9 个 Z 层**，没法改成 48×48，所以做法是：
把 53 版那块 48×48 的区域**原样、逐格**放进 144×144 地图的正中央（第 48–95 列 / 第 48–95 行），
其余位置在 Z=0 层补草地，其他层填空地（`#`）。中间那 48×48 一个小格都没改。

---

## 一、两份文件到底差在哪

| | v53（`53_arena.txt`） | v0.47（`47_arena.txt`） |
|---|---|---|
| 结构 | 一个文件里装多张图：`[ARENA:SMALL]`、`[ARENA:FOREST]`、`[ARENA:CLASSIC]` | 一个文件 = 一张图，没有分段 |
| 尺寸 | 每张图自己声明：`[DIMX:48]` `[DIMY:48]` | 固定 144×144，不能改 |
| 层数 | `[MAP_LEVEL]` 若干层，`[REPEAT_LAST_MAP_LEVEL]` 表示重复上一层（小巧的压缩写法） | 固定 9 层，`Z=-4` 到 `Z=4`，每层必须写满 144 行 |
| 每层行数 | 等于 `DIMY` | 恒为 144 |
| 行首标记 | `[ARENA:…]` 这种方括号标签 | `Z=-4, Lowest Level (must leave this line here)` 这类纯文本行 |

所以「不能直接复制」的真正原因是**外层语法和画布尺寸不同**，不是内容不同。

## 二、瓦片字符的含义没有变（这一点做过验证）

我拿 53 文件里的 `[ARENA:CLASSIC]` 和 47 的默认 `arena.txt` 做了逐格比对：
**9 层 × 144 × 144 全部完全一致，0 处不同**。
CLASSIC 在 53 里就是「和老版本一样的经典竞技场」，而它和 47 的默认图一模一样，
这就证明了从 47 到 53，地图字符（`# . P R F C + W w L l g T ~ ,`）的含义一路没改。

于是转换只需要做「重新排版」，字符照抄：

| 字符 | 含义 | 在小型竞技场里出现的位置 |
|---|---|---|
| `g` | 草地（有地板） | 整片场地 |
| `P` | 石块墙 | 中间椭圆场地的围墙 |
| `~` | 沙地（地板） | 椭圆场地内部 + 南侧出口的一小段 |
| `#` | 空地（无地板） | 场地以外的 8 个层（相当于天空/地下空腔） |

（不是水。DF 里水是 `W`，`~` 是沙。所以那圈东西是沙地竞技场，不是水池。）

## 三、Z 层怎么对齐（唯一需要做取舍的地方）

53 的层序是**自下而上**：第 1 个 `[MAP_LEVEL]` 对应 `Z=-4`。小型竞技场把草地放在第 1 层，
也就是原文件里它其实位于 `Z=-4`（最底层），上面 8 层全是空地。它的 `[START_CENTER:23:23:0]`
里的 `0` 是层序号（0 = 第 1 层），说明进图时镜头就停在这层。

到了 v0.47，镜头默认在 `Z=0`，而且不能改初始 Z。若照抄成 `Z=-4`，一进去会看到一片空荡荡，
得手动往下按 4 层才看得到场地。所以默认把**草地那层放到 `Z=0`**，和你进经典竞技场时的观感一致。

如果需要「1:1 照抄层号」的版本（草地仍在 `Z=-4`）：

```
python convert_arena.py --arena SMALL --anchor 4 --out 47_small_arena_z-4.txt
```

## 四、生成的文件长什么样

- 9 层，`Z=-4` 到 `Z=4`，每层 144 行 × 144 字符，CRLF 换行、纯 ASCII、末尾不带换行
  （和原版 `47_arena.txt` 的字节结构完全一致：189529 字节 / 1305 行）。
- `Z=0`：中间 48×48 是原样搬过来的竞技场，四周是 `g` 草地（和场地外圈无缝衔接，不会出现悬空的岛）。
- `Z=-4…-1`、`Z=1…4`：全是 `#` 空地。

## 五、怎么验证（都在这次交付里跑过）

```
python convert_arena.py --list      # 列出 53 文件里的三张图
python convert_arena.py --selftest  # 交叉验证 + 逐格比对
python make_preview.py              # 出预览图 preview_z0.png / preview_crop_check.png
```

`convert_arena.py --selftest` 会做两件事：

1. 把 53 的 CLASSIC 和 47 默认图对齐比较 → 9 层全部 0 差异（证明字符含义一致）；
2. 把生成结果重新解析回来，检查 9 层 / 144×144 / 内部 48×48 与源文件逐格比对 → 0 差异。

`make_preview.py` 出的 `preview_crop_check.png` 是「源图 48×48」和「从成品里抠出来的 48×48」并排，
两张完全一样，肉眼看即可确认没有走样。

## 六、安装步骤（v0.47.05）

1. 关掉游戏。
2. 备份 `Dwarf Fortress\data\init\arena.txt`（比如改名成 `arena.txt.bak`）。
3. 把 `47_small_arena.txt` 复制进去，改名为 `arena.txt`。
4. 启动游戏 → Object Testing Arena。

注意：竞技场的初始地形只在**游戏启动时**读一次，所以必须重启游戏才生效；
在竞技场里用手改的地形不会写回 `arena.txt`。

## 七、已知的取舍 / 可以再改的地方

- 受 0.47 固定 144×144 的限制，场地只有中间 48×48，外面那一大圈是同色草地。
  如果不想要这么大的草地，可以用参数把外围换成墙或空地：
  `python convert_arena.py --fill P`（`--fill` 是 Z=0 层场地以外的填充字符）。
- 场地外围那 8 层是空地而不是实心岩石。0.47 里地板是独立存在的，
  所以草地不会塌，只是往下挖（竞技场里也挖不了）能看到空腔。若要填实心，可自行把非 0 层改成 `P`。
- `~` 沙地在游戏里每次进入会随机选一种沙/土壤的材质，这是 DF 本身的行为（wiki 也这么写）。
